# 垃圾帖宝藏场：意图卡与报喜小站

- 根目录：意图卡生成器；example.html为完整填写范例。
- progress/：发布进度与报喜图片生成器。
- 生成意图卡后，点击“把发布计划带入报喜页”，传递昵称、平台、天数和目标总数；不会传递个人意图、应对计划、愿景或Faces照片。
- 同一浏览器可读取最近一次带入的计划。已有进度只在用户确认保存计划后更新，保留已发布数量与记录。
- 只有旧意图卡图片时，可以选图识别，核对并补全后保存。OCR使用Tesseract.js与本地托管的语言数据，在访客浏览器里处理，不上传图片或识别文字。
- 识别组件按需加载。首次识别需要下载识别组件与语言数据，请保持页面打开；结果可能存在误差，不自动把识别值当成已确认计划。
- 报喜记录仅在当前设备的当前浏览器保存，支持备份与导入。不同设备不会自动同步。
- 累计数可通过“调整累计条数”拖动或输入，保存后生效，不新增报喜。修正以当前报喜记录数为起点，后续报喜继续累加；原记录保留。撤销仅适用于最近一次修正之后新增的报喜，避免撤销旧记录再次改变已确认的累计数。旧备份无需修正信息也可导入。
- 源码是静态HTML/CSS/JavaScript，可由GitHub Pages直接托管，无构建与服务器密钥。
- 报喜卡品牌、鼓励语与口号居中；平台独立高亮，植物图案仅放在海报边缘。感受未填写时不显示个人感受段落。
- 鼓励语为30句预先编写的文案，每句含emoji，按报喜次数轮换；当前不调用生成式AI服务。
- 计划可以包含多个平台（用顿号、逗号或斜杠分隔）。每次报喜勾选实际发布的平台，海报与记录只保留本次选择；新增条数按所选平台实际发布的总条数填写，例如两个平台各发1条，填写2条。平台选项从已保存的计划动态生成，支持自定义平台名称。旧记录不推断平台，旧备份仍可导入。
